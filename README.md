# 單字日課 — 會考 2027 複習 App

> 版本：v3.2（2026-11-11）。本版本可在靜態網站使用；**雲端帳號、導師查核必須另行啟用 Supabase**。請先用測試帳號驗證，再正式給學生使用。

## 已包含的功能

- 每日目標三選一：輕量組 **15** 個、標準組 **30** 個、考前衝刺組 **50** 個（每天成功答對的不同詞目數；**包含**到期複習與新字）。當天開始任務後，變更目標從次日生效。
- 到期詞優先、答錯當天再練；長期依 1／3／7／14／30／60／90 天等間隔複習。較熟悉詞目會抽到英文拼寫題。
- 2027/5/15–16 會考倒數、首輪接觸的**估算**完成日期、學習月曆、字庫搜尋、中文釋義與有提供的例句。
- 本機進度儲存，以及個人進度 JSON 匯出／匯入。清除瀏覽器資料、無痕模式或更換裝置可能造成未同步資料遺失。
- **可選的 Supabase 雲端模式**：Email 註冊登入、跨裝置讀取／同步、班級加入申請、導師核准或移除錯誤申請、昨日完成名單、CSV 下載。

## A. 先把網站放上 GitHub Pages（不需要寫程式）

請將本 ZIP 內下列檔案**一起**放在同一個網站資料夾（不要只上傳 `index.html`）：

```text
index.html
app.js
styles.css
word-data-full.json
config.js
sw.js
manifest.webmanifest
```

1. 在 GitHub 建立新的 repository，或放入原有單字 App repo 的網站根目錄。若和其他教學網站共用 repo，請放在獨立資料夾，避免覆蓋其他單元的 `index.html`。
2. 開啟該 repository 的 **Settings → Pages**，選 **Deploy from a branch → main → /(root)**（若放子資料夾，請用相應 Pages 設定或路徑）。
3. 開啟 GitHub Pages 網址，等候載入後，首頁應顯示「2,005 筆官方參考詞目」，並可選 15／30／50 個。
4. 先選輕量組，做完 15 個詞，再到「學習月曆」檢查當日標記。重新整理也應保留進度。

此時為**本機試用版**：學生雖可練習、儲存本機進度，但老師**不能**遠端看到已完成名單。要開啟遠端查核請做 B。

## B. 啟用雲端帳號與導師查核（Supabase）

請依學校資訊安全／個資政策確認是否可讓學生使用第三方雲端帳號。未經核准請先保持本機試用模式；測試時使用測試帳號與假座號。

1. 建立一個**專門給這個 App** 的 Supabase 專案，記下 Project URL 和 **publishable / anon key**。**不能把 `service_role` / secret key 放進 GitHub 或 `config.js`**。
2. 進入 Supabase 的 **SQL Editor**，貼上 `setup_supabase.sql` 的完整內容並執行。此 SQL 僅供首次建立專案表格、權限、函式與 2,005 個官方詞目 ID 使用；**不要在已建立舊版同名表格的專案直接重複執行**。
3. 到 Supabase 的 **Authentication** 設定 Email 登入與寄送確認信。於 URL Configuration 設定自己 GitHub Pages 網址作為 Site URL，並設定合適的 Redirect URLs。
4. 修改網站 `config.js`：

```js
window.VOCAB_CLOUD_CONFIG = {
  url: 'https://YOUR-PROJECT.supabase.co',
  anonKey: 'YOUR-PUBLISHABLE-OR-ANON-KEY'
};
```

5. 將修改後的 `config.js` 上傳到 GitHub，重新整理網站，進入「帳號設定」，用教師的 Email **建立帳號、完成信箱驗證**。
6. 由專案擁有者再次進入 Supabase SQL Editor，**只在教師帳號註冊完畢後**執行下列指派語句（以教師實際 Email 取代示例）：

```sql
insert into public.teachers(user_id)
select id from auth.users where email = 'TEACHER_EMAIL@example.com'
on conflict do nothing;
```

7. 教師登出再登入，應出現「導師查核」頁面。建立班級與不容易猜中的邀請碼（建議亂數至少 10 位），交給學生。
8. 學生各自註冊／驗證 Email、登入後在「加入導師班級」輸入邀請碼與座號。**導師需核准加入**，學生才會列入查核表。
9. 讓測試學生完成配額。**隔天**進入「導師查核」，就能查看昨日完成名單並下載 CSV；可先用不同測試帳號檢查正確性。

**請注意：此版本不包含已部署的 Supabase 專案、真實帳號或線上連線測試。** 要確認雲端功能能用，必須先完成上面的部署與雙帳號測試。

## C. 給學生與導師的使用規則建議

- 聯絡簿小日記抵免：以**導師後台「昨日完成」**為依據，每日配額（15／30／50）須在該日台灣時間內完成；同一單字當天只計一次。
- 若網路斷線、學生用本機試用模式、未加入班級或完成紀錄未成功寫入雲端，導師可能看不到完成標記；建議提供合理補登／查證管道。
- 「雲端完成」是**伺服器收到詞目通過事件並記錄時間**，不是防作弊考試。技術熟悉的使用者仍有能力繞過瀏覽器題目直接送出通過事件，因此不可視為高度防弊或正式評量。
- 出於學生隱私，班級內盡量使用「座號＋暱稱」，不要要求上傳完整姓名、成績或其他不必要的個資。

## D. 字庫內容與限制

目前 `word-data-full.json` 已依上傳的《英語文課程綱要》附錄五，收錄**基本詞目 1,211 + 延伸詞目 794 = 共 2,005 個列示詞目**。括號內變化形視為同一詞目的別名，不一定獨立出一筆。

比較舊 App 後，**470 條未找到的官方詞目**已新增中文釋義，但這些新補項目的**詞性、例句仍未補齊**；**全部 2,005 條的英文例句與中文釋義仍需人工逐筆檢查**。詳情請看 `字庫檢核報告.md` 和 `vocabulary_audit.csv`。這是內容品質的重要未完成事項，**不能宣稱全部例句已校對完成**。

## E. 使用時可能遇到的問題

| 現象 | 原因／處理 |
| --- | --- |
| 頁面顯示「字庫載入失敗」 | 通常是只上傳 index.html，漏傳 JSON 或 JS；請確認七個網站檔案位於同一相對路徑，並用正式網站網址開啟，不要直接雙擊本機 HTML。 |
| 能練習但找不到登入欄位 | `config.js` 尚未填好，或 Supabase JavaScript 程式庫載入失敗。 |
| 註冊後無法登入 | 查看確認信、檢查 Supabase Authentication 設定。 |
| 登入後沒看到導師查核 | 尚未以 SQL 將註冊帳號加入 `teachers`，或需要登出重登。 |
| 導師看不到學生 | 學生還沒加入、待核准、練習未雲端確認，或沒有該日期的完成紀錄。 |
| 學生換裝置後進度不一致 | 必須先在兩台裝置登入**同一個帳號**且有網路；避免兩台同時學習（目前不是可衝突合併的即時協作系統）。 |
| 網路斷線 | 已快取的網站可能可以本機練習，但**離線不能保證登入、上傳或導師即時查核**；恢復網路後請再開啟網站確認。 |

> 請使用 HTTPS（GitHub Pages 預設提供）。本版已有學生端瀏覽器測試；**尚未連接真實 Supabase 測試跨裝置帳號與後台**，正式用於全班前務必做一次端到端試行。
